# Российское хранилище: файлы и оплаты, этапы 1–3 — 22 сентября 2026

Принята существующая схема: Бот3 в Нидерландах обращается к TEMLI_RUS_TEST
в России. TEMLI_PROD_CANDIDATE остаётся остановленным. Новые контейнеры
не требуются. Этот этап не подтверждает юридическую готовность к продажам.

## Что готово

- storage_server.py: POST /v1/files/read, /v1/files/write и /v1/files/delete
  с прежним Bearer-секретом.
- Разрешены book.xlsx, receipt_assets/{logo,signature,qrcode}.{png,jpg,jpeg},
  receipts/<имя>.pdf в корне и teacher_data/<числовой ID>/.
- Файлы до 8 МиБ, передаются в JSON как base64; API хранит байты, не проверяет
  содержимое как изображение/Excel/PDF. Проверка формата нужна в прикладном коде.
- Каждая запись требует expected_version (SHA-256 или null при создании).
  Устаревшая версия получает 409. Замена файла атомарна, предыдущие байты в .bak.
- remote_storage.py: read_file/write_file/delete_file, проверка SHA-256, без записи
  на локальный диск. Перед изменением или удалением обязателен read_file.
- ZIP schema=2 включает JSON и разрешённые файлы, проверяет их контрольные суммы.
  Старые JSON ZIP schema=1 по-прежнему поддерживаются.
- /health дополнительно возвращает capabilities: json, files-v1, backup-v2.

## Что подключено в Бот3 на этапе 2

- Загрузка логотипа, подписи и QR сохраняет оригинал в российском хранилище.
- При формировании чека нужные изображения проверяются по SHA-256 и атомарно
  материализуются во временном каталоге Бот3.
- При смене расширения старый вариант изображения удаляется условным запросом.
- Недельный PDF снова доступен: он собирается из российских JSON-данных во
  временный файл, отправляется в Telegram и удаляется.
- Чеки также создаются как временные PDF; постоянные изображения остаются в РФ.
- SCHEDULE_WEBAPP_URL читается из окружения, поэтому тестовый frontend не будет
  потерян при обновлении bot.py.

## Что подключено на этапе 3

- `/v1/transactions/payment` единым commit сохраняет `schedule.json`,
  `payments.json` и `book.xlsx` для одного преподавателя.
- До записи проверяются версии всех файлов; конфликт не меняет ни один файл.
- Сервер сначала создаёт durable-журнал. При ошибке все файлы откатываются, а
  после аварийного перезапуска подготовленная операция завершается или откатывается
  до открытия HTTP API.
- Повтор того же запроса после потери ответа идемпотентен; клиент автоматически
  повторяет временно оборвавшийся запрос с тем же идентификатором.
- Книга материализуется во временном каталоге Бот3, но её постоянная версия и
  история оплат находятся на российском сервере. Скачивание XLSX снова доступно.
- Журналы ограничены 200 записями на преподавателя и исключены из ZIP-бэкапов;
  сами актуальные JSON/XLSX входят в резервные копии.

## Порядок публикации

1. Скачать свежий существующий архив TEMLI_RUS_TEST из /app/data/temli-backups.
2. В backend-репозитории, ветка main, обновить storage_server.py.
3. Полностью пересобрать TEMLI_RUS_TEST (российское хранилище).
4. Проверить его /health: status=ok, capabilities содержит files-v1,
   payment-tx-v1 и backup-v2.
5. В рабочей ветке Бот3 обновить remote_storage.py и bot.py.
6. Полностью пересобрать только Бот3; TEMLI_PROD_CANDIDATE не запускать.
7. Открыть мини-приложение, проверить логотип/PDF, провести тестовую оплату,
   скачать книгу учёта и затем отменить тестовую оплату.

Главный файл TEMLI_RUS_TEST остаётся storage_server.py; переменные прежние.
Не загружать полный старый release_remote_json_test или архив 0.2: они не являются
комплектом этого обновления.

## Проверки и ограничения

18 тестов test_remote_storage прошли: старый JSON API и реальный процесс bot.py,
файловый HTTP-клиент, токен, пути, версии, лимит размера, отдельные каталоги
преподавателей, SHA-256, повреждённые архивы, совместимость и восстановление.
Проверка отдельных каталогов не заменяет проверку Telegram-авторизации:
секрет российского сервиса даёт доверенному backend доступ ко всему хранилищу.

Архивы хранятся на том же диске. Полное восстановление по-прежнему требует
остановить пишущего клиента; оно заменяет файлы по одному, оставляет файлы,
отсутствующие в архиве, и не является атомарным переключением всей базы.
Не применять на живых данных как часть этой публикации.
