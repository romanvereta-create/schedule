# Telegram-only proxy на BotHost

## Область изменения

Основной бот (включая getUpdates), персональные боты и служебные Telegram-
уведомления используют TELEGRAM_PROXY_URL. Без неё Telegram работает напрямую.
При недоступности заданного прокси автоматического обхода напрямую нет.
Redirects выключены; TLS-проверка сертификата Telegram остаётся включённой.

Mini App, storage API, файлы и backup не подключаются к этому транспорту.
Глобальный proxy/opener не устанавливается. На старте запрещены непустые
HTTP_PROXY, HTTPS_PROXY, ALL_PROXY (включая нижний регистр), чтобы они не
направили urllib-трафик хранилища через иностранный узел.

PDF-чеки и прочие файловые Bot API операции при включённом прокси запрещены.
Скачивание файлов через российский backend не изменено. Это сознательное
ограничение требования «не передавать пользовательские файлы через proxy».

## Настройка

1. Получить отдельный SOCKS5 или HTTP CONNECT proxy, доступный из Новосибирска.
   MTProto-прокси из Telegram не подходит. Требуются host, port и при наличии
   user/password. Не присылать пароль в чат, не сохранять URL в Git.
2. Прокси должен разрешать CONNECT/TCP только к api.telegram.org:443,
   не расшифровывать TLS, не кэшировать и не писать тела запросов. На сервере
   прокси ограничить доступ аутентификацией/firewall; не делать открытый proxy.
   Настройки и географию прокси этот код проверить не может.
3. Развернуть именно сборку с telegram_transport.py и обновлёнными requirements.
   Нужна пересборка Docker, чтобы установить socksio. Старый pinned
   candidate_bootstrap.py не использовать: он устанавливает прежний релиз.
4. В переменных только кандидата добавить ОДИН вариант:

   TELEGRAM_PROXY_URL=socks5://USER:PASSWORD@HOST:1080

   либо TELEGRAM_PROXY_URL=http://USER:PASSWORD@HOST:3128

   Поддерживаются также socks5h:// и https://. Спецсимволы в логине/пароле
   кодировать percent-encoding. Порт обязателен. Не задавать HTTP(S)_PROXY.
5. Перезапустить только кандидата. В логах будет «TEMLI Telegram transport:
   proxy» без адреса и пароля. Старый poller с тем же Telegram-токеном остановить.
6. Проверить getMe, несколько /start, фактический ответ и открытие Mini App,
   сохранение/снятие оплаты на вымышленных данных и повторное открытие.
   Проверить storage/backup отдельно: наличие proxy не доказывает их географию.

## Границы обещаний

Совместимо с используемым Python/Docker-стеком BotHost, но работа из конкретного
контейнера зависит от доступности proxy. Без реального адреса провести внешний
сквозной тест нельзя. При удалении TELEGRAM_PROXY_URL возвращается прямой режим.

Это транспортная правка, не реализация всего приложенного архитектурного ТЗ.
Telegram updates, chat_id и тексты существующих уведомлений идут внутри TLS
через proxy к Telegram. Telegram получает эти данные; приложение пока не
переписано на исключительно нейтральные уведомления. Прокси без TLS interception
видит сетевые метаданные, но отсутствие логов на нём требует отдельной проверки.
Отсутствие зарубежной БД само по себе не означает отсутствия трансграничной
передачи или юридического соответствия. Не включать для реальных данных без
оценки этих потоков.
