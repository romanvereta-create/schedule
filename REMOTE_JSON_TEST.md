# TEMLI: тест российского JSON-хранилища

Это изолированный стенд. Боевой бот и его данные не переносятся.

## Схема

- Российский BotHost запускает только `storage_server.py` и хранит JSON в
  `/app/data/temli`. К Telegram он не обращается.
- Отдельный тестовый бот в Нидерландах запускает обычный `production_server.py`
  и обращается к российскому серверу по HTTPS.
- Доступ разделён на три независимых секрета: данные приложения,
  чтение копий и административное восстановление. Секреты нельзя отправлять
  в чат, добавлять в GitHub или печатать в логах.

## Российский экземпляр

Главный файл:

```text
storage_server.py
```

Переменные:

```text
DATA_DIR=/app/data
TEMLI_STORAGE_APP_TOKEN=<случайный секрет не короче 32 символов>
TEMLI_STORAGE_BACKUP_READ_TOKEN=<другой случайный секрет>
TEMLI_STORAGE_ADMIN_TOKEN=<третий случайный секрет>
TEMLI_STORAGE_INITIALIZE_EMPTY=true
```

Домен и HTTPS должны быть включены. После запуска `/health` возвращает
`service=temli-storage`. Переменная инициализации создаёт только новое пустое
хранилище и отказывается работать поверх неизвестных файлов.

## Нидерландский тестовый бот

Главный файл:

```text
production_server.py
```

К обычным тестовым переменным добавить:

```text
TEMLI_STORAGE_URL=https://<домен российского экземпляра>
TEMLI_STORAGE_APP_TOKEN=<тот же app-секрет>
TEMLI_STORAGE_BACKUP_READ_TOKEN=<тот же backup-read-секрет>
```

`TEMLI_STORAGE_ADMIN_TOKEN` на сервере бота задавать запрещено. Старый
`TEMLI_STORAGE_TOKEN` поддерживается только на время поэтапной миграции и после
проверки новых ключей должен быть удалён с обеих сторон.

Не задавать `TEMLI_STORAGE_ALLOW_HTTP`: в интернете разрешён только HTTPS.
При недоступности или неверном ключе бот остановится до запуска Telegram polling.

### Контракт сборки Bot3

В BotHost должен быть включён режим **«Использовать собственный Dockerfile»**.
Корневой `Dockerfile` фиксирует Python 3.11 и команду запуска
`python -u bot.py`; Node/npm для этого сервиса не используются. Перед
публикацией проверить контракт локально:

```text
python -m unittest -v test_docker_contract.py
```

Тест запрещает корневые Node-манифесты (`package.json` и lock-файлы), Node
команды в Dockerfile и любое изменение Python entrypoint. Если тест не прошёл,
Bot3 не пересобирать.

После публикации выполнить безопасную публичную проверку без токенов:

```text
python check_bot3_postdeploy.py
```

Она параллельно проверяет health Bot3, реальную связь Bot3 с хранилищем,
наличие резервных копий и health российского сервера.

## Текущий контракт

Удалённо хранятся расписания, ученики, настройки, реестр преподавателей,
приглашения, привязки, журналы уведомлений и история платежей в JSON.

Удалённые бинарные объекты, платежи, чеки, книга учёта и PDF-экспорт включены.
До закрытия всех пусковых ворот из `docs/PRODUCTION_READINESS.md` использовать только
синтетические тестовые данные.
